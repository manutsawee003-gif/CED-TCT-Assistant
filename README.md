# CED/TCT Assistant

## Typhoon query understanding

Create `.env` from `.env.example` and set `TYPHOON_API_KEY` (never expose it in the browser). Typhoon is called only by the backend and returns structured query interpretation; it is never used as the answer generator. If the key is absent, rate-limited, the request times out, or the model returns invalid JSON, the chatbot continues with the existing local hybrid retrieval.

The request flow is: user question → Typhoon interpretation (normalized query, intent, validated entities, keywords, ambiguity) → TF-IDF/fuzzy/entity hybrid retrieval over `Dataset รวม` → score threshold/clarification decision → exact `answer` field from the selected Dataset record. Answers are never generated by Typhoon.

The extended pipeline keeps the original system and adds: bounded relevant conversation turns → structured constraints and multi-query expansion → candidate pool of eight Dataset records → optional Typhoon candidate-ID reranking only when the top score gap is small → calibrated confidence. It indexes question/category as the primary semantic representation and uses answer text as a separately weighted semantic signal, so a broad answer cannot dilute a precise question match. Reranking receives Dataset candidates only; the final response reads the selected record's `answer` field verbatim. For a Typhoon-classified broad question, up to three threshold-qualified Dataset records may be returned as separate, traceable entries.

Run `npm run evaluate:pipeline` for the Dataset-grounded semantic fixture suite. It compares retrieval without structured interpretation against the same cases with validated structured-query fixtures. The fixtures model the expected Typhoon JSON contract; configure a real key before using live Typhoon behavior in production.

Set `DEBUG_CHAT=true` to log the original question, Typhoon interpretation, normalized query, intent/entities, Dataset candidates and component scores, selected record, and final Dataset answer. The retrieval calibration values in `.env.example` are based on the existing scoring formula and can be adjusted without code changes.

User preprocessing preserves the original text and adds NFC cleanup, zero-width/whitespace cleanup, compact Thai spacing-tolerant text, and Dataset-aware typo alternatives. Corrections are produced only from terms/entities already present in the Dataset, carry confidence, and are used as additional search representations rather than replacing the original question. Numeric identifiers are never auto-corrected.

## Deploy บน Vercel

Deploy **โฟลเดอร์โปรเจกต์นี้ทั้งโฟลเดอร์** ผ่าน Git repository หรือ Vercel CLI (`vercel --prod`) ห้ามลากเฉพาะโฟลเดอร์ `dist` ไป deploy เพราะ `dist` มีเฉพาะหน้าเว็บและไม่มี `/api/chat`.

ไฟล์ `api/chat.js` และ `api/health.js` เป็น Vercel Serverless Functions ซึ่งอ่าน Dataset จาก `data/Dataset_CED-TCT1_การรับสมัคร.xlsx` แบบ read-only. หลัง deploy ให้เปิด `/api/health`; ต้องได้ JSON ที่มี `ok: true` และ `records: 1249` ก่อนทดสอบหน้า Chat.

## การทำงาน

- API: `POST /api/chat` ด้วย body `{ "message": "CED ค่าเทอมเท่าไหร่" }`
- Server โหลดเฉพาะ sheet `Dataset รวม` ที่เริ่มทำงาน แล้ว cache ข้อมูลและ search index (1,249 แถว)
- Query Understanding สร้าง canonical query จาก normalization, dataset-driven intent, generic entity extraction และ conversation context
- Domain index สแกน Dataset รวมเพื่อสร้าง program, topic, course-code, ปีการศึกษา, ระดับการศึกษา และ admission-round catalog
- Hybrid retrieval ใช้ corpus vector similarity (TF-IDF cosine), lexical overlap และ fuzzy score จากนั้น re-rank ด้วย entity compatibility, intent/category compatibility และ conflict penalty
- คะแนนต่ำกว่า `0.35` หรือมี retrieval evidence ต่ำจะตอบว่าไม่พบข้อมูล; candidate ที่สูสีกันแต่ต่าง entity สำคัญจะถามกลับ
- ตั้ง `DEBUG_CHAT=true` ใน `.env` เพื่อดู original/normalized query, intent, entities, inherited context, candidates, component scores, conflict และ ambiguity decision ใน terminal

รัน `npm test` เพื่อตรวจ 10 กรณีทดสอบ, `npm run evaluate` เพื่อประเมิน query variations และ `npm run build` เพื่อตรวจ production build
